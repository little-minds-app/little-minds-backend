# Activity ingestion — LMP-50 contracts / LMP-51 backend candidate

LMP-50 defined ActivitySessionV1 and ActivityEventV1 (schema_version `1.0.0`), privacy validators, and server-consent evaluation. LMP-51 now adds an **unmerged backend candidate**:

- `POST /v1/events/batch` behind existing `ParentAuthGuard`; parent identity comes exclusively from verified bearer session.
- `ActivityBatchAdmissionService` validates bounded event/session documents; UUIDs remain stable across retry.
- `ActivityIngestionService` verifies parent-owned device, child session and content variant, and authoritative effective consent.
- PostgreSQL transaction writes a global `activity_ingest_keys` claim with exactly one child or parent-only event; same content replays return `duplicate_noop`, changed-ID content conflicts are rejected.
- Missing session metadata is `retryable`, not a permanent out-of-order loss; session completion can update a previously started session without changing identity.
- Parent-only events do not invent child play sessions. Consent policy and provenance are persisted.
- Validation rejects unknown schemas/fields and PII; raw event data must not be logged.

The **canonical** OpenAPI path is now published in this unmerged feature branch under `contracts/openapi.yaml` (version `0.12.0`); Dart/TypeScript generated clients were regenerated by the repository's existing branch-scoped sync workflow. This is **not a production deployment**. Final green contract-drift CI and independent code/security review are mandatory before merge.

Test entry points: `src/modules/activity-ingestion/*.spec.ts`, `test/activity-ingestion.db.spec.ts` (real PostgreSQL) and `test/activity-ingestion.e2e-spec.ts`.
